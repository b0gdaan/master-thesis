# Комплект для следующей исследовательской работы

Подготовлен 11 сентября 2026 года после сообщения Богдана Бабаева об успешной защите. Основание: история Git и локальные материалы проекта `b0gdaan/master-thesis`, состояние исходников `1fe8f4e`, переписка о подготовке работы и защиты.

## Как начать

1. Открой [MASTER_PROMPT.md](MASTER_PROMPT.md). Это готовый самостоятельный промпт для нового диалога с исследовательским ассистентом.
2. Укажи новую тему и известные ограничения в начале промпта. Остальные поля можно оставить как «не определено».
3. Приложи [HISTORY.md](HISTORY.md) и [PIPELINE_AND_TESTS.md](PIPELINE_AND_TESTS.md), если новый ассистент поддерживает файлы. Промпт содержит краткий исторический контекст и работает также без вложений.
4. Первым результатом должны стать постановка исследования, экспериментальный протокол и маленький работающий пример, проходящий путь от данных до проверенной таблицы результатов.

Короткое вводное сообщение для нового диалога:

> Я защитил магистерскую работу о прогнозировании межрыночных зависимостей. Теперь хочу исследовать тему: [НОВАЯ ТЕМА]. Используй приложенный промпт, историю предыдущего проекта и технические требования. Начни с постановки задачи и минимального воспроизводимого эксперимента. Зафиксируй неизвестные параметры, создай структуру проекта и журнал решений. Переходи к следующим этапам после проверки результатов предыдущего.

## Что переносится в новую тему

Переносится способ работы: проверяемый вопрос, базовый метод сравнения, фиксированные данные, журнал экспериментов, тесты, анализ ограничений и сборка конечных материалов из результатов.

Конкретные параметры предыдущей работы, включая Bitcoin, DCC-GARCH, 24 эксперимента, 800 наблюдений и 81 тест, относятся к её предметной области. В новой теме число методов, метрики, размеры выборок и схема проверки определяются новой исследовательской задачей.

Успешная защита подтверждена сообщением автора. Протокол заседания, оценка и точная фактическая дата защиты в рамках подготовки комплекта не проверялись. Даты истории разработки взяты из Git; они не являются табелем времени или полным журналом всех действий.

## Проверка исходного проекта

11 сентября 2026 года существующий набор `tests/` прошёл проверку: **81 passed in 2.52s**. Это проверка на уже сохранённых локальных данных и результатах. Полный пересчёт моделей, загрузка данных, сборка диссертации и развёртывание сайта в эту проверку не входили.

При этом текущая `.venv` не содержала `pytest`; успешный запуск выполнен установленным Python 3.14.0, где необходимые зависимости присутствуют. Это конкретный пример того, зачем следующему проекту нужны проверка окружения и инструкция восстановления.

Требования нового проекта намеренно учитывают обнаруженные ограничения предыдущего: неполное покрытие причинных границ тестами, пропуск поздно добавленной абляции общим runner-ом, продолжение сборки после неудачных этапов и расхождение документации с актуальными артефактами.

Комплект подготовлен локально. Он не создаёт новый исследовательский проект и не запускает обучение по новой теме.
